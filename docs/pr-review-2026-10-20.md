### [P3，已修正並重測] 未支援 PDF stream filter 會逸出原始例外

原始位置：`prototypes/parsing/parser.py` 的 `page.extract_text()` 與例外清單。初審使用 pypdf 產生一頁 PDF，將該頁 `/Contents` 設為帶有 `/Filter /UnsupportedFixtureFilter` 的 encoded stream，再呼叫 `parse_document(bytes, 'synthetic.pdf')`，實際得到 **`NotImplementedError: Unsupported filter /UnsupportedFixtureFilter`**，不是 `ParseError`；只捕捉 `ParseError` 的呼叫端會中斷。這是原型低優先度失敗契約問題，沒有發現 app 洩漏或授權影響。

後續修正已由協調者加入，審查者重新讀取並獨立驗證：現在 `prototypes/parsing/parser.py:109–110` 捕捉 `NotImplementedError` 並轉為 `ParseError('unsupported_pdf_feature')`；`test_unsupported_pdf_filter_has_stable_error` 使用同類 encoded stream 測試穩定錯誤碼，已通過。此 finding **已解決，沒有剩餘修正要求**。下方重現保留為失敗歷史；目前執行應得到 `ParseError: unsupported_pdf_feature`。審查者未修改原型程式。

重現輸入在記憶體產生，核心步驟如下；不需要外部 PDF 或磁碟檔案：

```python
from io import BytesIO
from pypdf import PdfWriter
from pypdf.generic import EncodedStreamObject, NameObject
from prototypes.parsing.parser import parse_document

writer = PdfWriter()
page = writer.add_blank_page(width=100, height=100)
stream = EncodedStreamObject()
stream._data = b'BT (synthetic text) Tj ET'
stream[NameObject('/Filter')] = NameObject('/UnsupportedFixtureFilter')
page[NameObject('/Contents')] = writer._add_object(stream)
output = BytesIO()
writer.write(output)
parse_document(output.getvalue(), 'synthetic.pdf')
```

其他核對結果：TXT `start/end` 是移除 UTF-8 BOM 後 `source_text` 的 codepoint 範圍；去掉段落外圍空白後，`source_text[start:end] == segment.text`，不是原始 bytes offset。CRLF 與 LF 空白行切段不會改寫段內金額、料號或換行。PDF `page:1` 等標籤來自檔案實體頁次，不宣稱等於紙面印刷頁碼；任一空白／不可讀頁會使整份失敗，沒有部分成功結果可進索引。PDF 抽文字仍可能有字序／字形或表格關係錯誤，不能由這兩頁簡單測試推論一般中文 PDF 品質。`requires_review=True`、`indexable=False` 與原型定位一致。

預設 2 MiB 原始 bytes、20 頁、200,000 字元的檢查存在，但頁面展開及 `extract_text` 在字元長度檢查之前發生；沒有程序隔離、wall-clock／memory／解壓後 stream 上限。函式 docstring 已明確揭露不能限制解壓與 CPU，因此本次不將其宣稱為惡意 PDF 防護，也不以本原型作為正式上傳端點。
