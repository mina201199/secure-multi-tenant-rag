# 核心評估題庫 v1.0.0

這是尚待 RAG 實作後使用的 **30 題由 AI 逐題指定的規格題庫**，不是模型成效報告。題目、預期答案、權限條件及引用範圍由 AI 撰寫代理逐題建立，並進行來源事實與規則自我一致性檢查；**尚未經獨立人工審核簽核**，不得宣稱已通過人工驗收或已完成 M4-01 的人工校對要求。未執行目標 RAG 模型、檢索實驗或付費 API。

`core_questions.json` 是評估契約，`fixtures/corpus.json` 是獨立虛構文件、帳號及 ACL 快照。`fx-a` 青岑與 `fx-b` 白嶼、所有 `fx-*` 帳號與額度均為本題庫新增的**提案測試資料**，不是目前資料庫或 UI demo 的 seed。本文不代表已匯入文件、建索引或建立帳號。

目前 `app/bootstrap.py` 的 seed 是甲公司／乙公司，各有出差補助規定、料件清冊（試行）、主管會議紀錄及封存舊規定；每日交通額度分別 NT$1,500／NT$3,000，料件 A-1001／B-1001 規格分別 M8x30／M10x40。此題庫另用 NT$1,600／NT$3,200 和 AX-101／AX-101R 等資料，避免將新情境誤述成現有 seed。`001_m1_core.sql`、`002_m2_versions.sql` 與 README 的公司、版本 ACL、目前有效 ready、封存與角色規則是權限契約依據；版本建立、歷史調閱、RLS、RAG 及評估執行仍是後續工作。

## 不接資料庫的完整性檢查

於專案根目錄執行：

```powershell
python -m unittest discover -s evals/tests -p test_eval_fixtures.py -v
```

僅使用 Python 標準函式庫，不載入 app、不讀 `.env`、不連資料庫、不呼叫模型。檔案位於 `evals/tests/`，因此不受 `tests/conftest.py` 的 autouse bootstrap 影響；不要為執行這組檢查而修改或初始化現有資料庫。安裝 pytest 的環境也可用 `python -m pytest evals/tests/test_eval_fixtures.py -q`。一般 `pytest tests` 不會自動收集此目錄，CI 應明確加上它。

檢查涵蓋數量、唯一性、欄位、版本對應、帳號與公司關係、跨公司 ACL、目前版本唯一性、引用行號、答案關鍵事實與來源一致性、引用資格及 dev／acceptance 類型覆蓋。這些是資料品質與靜態契約測試，不能證明實際系統隔離、模型忠實度或回答正確率。

## 欄位與引用契約

每題具有 `account`、`company`、`relation`、`authorization`、`version_status`、`question`、`expected` 及 `allowed_evidence`。角色與啟用狀態由 corpus 中帳號取得；主管及管理員身分不包含私人內容閱讀權。`authorization` 是該題情境判斷，並非可由使用者提交的權限。`version_status` 列出相關候選／干擾版本，**不是允許送模型的清單**。`current_ready_foreign` 即使 ready 仍禁止跨公司存取；`historical_ready_reader` 即使有舊版 ACL 也不能進入一般問答。

引用格式 `a-travel-v2:L1` 指向 corpus 特定版本 `lines` 陣列第 1 行。這是穩定的人工來源位置，並非 PDF 頁碼或未來 chunk ID。未來匯入器須將這些位置映射為實際文件／版本／chunk／來源位置，保留對照，不得將 fixture ID 當作現有資料庫 ID。評估只提供來源文字與位置，不預先指定切塊結果。

`expected.answer` 是語意參考答案，允許合理改寫；`required_facts` 是必須傳達的事實，`forbidden_facts` 是本題特別需排除的錯誤或洩漏，**不是完整安全判定規則或僅靠字串比對的評分器**。數字、單位、料號及其關係都要正確。無證據、無權限、失效帳號或不可搜尋版本須拒答；無權限時不得揭露私人來源的標題、存在、片段或精確內容。一般問答不支援獨立歷史調閱，即使 owner 提問也只用目前有效版本。

`allowed_evidence` 是每題足以支持答案的引用位置白名單，**不是檢索輸入或完整授權文件清單**。拒答題為空，不代表使用者完全沒有其他可讀文件。未來系統須先自行按可信身分與版本 ACL 過濾，再檢索；不得把這個答案鍵用作檢索篩選捷徑。回答題須引用必要支持行，不能只列一個同文件但不支持答案的引用；拒答不得帶出禁止來源的引用。

演練文件第 2 行故意包含其他公司額度及私人專案代碼的**字面惡意指令**。該行作為可讀文件資料可能進入授權檢索上下文，但不能成為平台指令或支持那些公司事實的證據。C14／C27 檢查忽略命令並回答安全演練事實；若這些字串出現在模型上下文，不能僅憑字串判定取到了私人／外公司來源。真正的來源越權須依傳出的文件、版本與 chunk ID 判定。產出這些與問題無關的字串仍是答案污染；應另記錄被允許傳送的惡意來源行，避免混淆成「從私有來源洩漏」。

## 開發與保留驗收

- `dev`：C01–C18，共 18 題，可用於開發、除錯及調整提示。包括停用帳號與新版不繼承舊 ACL。
- `acceptance`：C19–C30，共 12 題，規劃作為保留驗收；首次正式評估前凍結答案鍵與設定，不拿失敗題反覆調參後再稱未見驗收。兩個 split 都包含跨公司、無答案、料件差異、同公司無權限、角色無自動權、版本、不可搜尋狀態及注入案例。

保留題目前仍公開在同一儲存庫，只是**程序上的保留**，不是密封盲測；任何看過／用過答案鍵的模型或調參流程應在報告標示污染，另建新題才能主張新保留集。這 30 題也不是 README 所要求至少 100 題的完整自動驗收集。

獨立人工審核時應逐題核對事實、引用行、公司與 ACL、版本狀態、拒答是否洩漏、料號單位對應及 split 分布，再記錄真實審核者、日期及修訂；不要預填審核人或補造簽核。

## 後續評估與版本管理

尚未提供 RAG runner、匯入器或成果指標。接上實作後，先在獨立測試資料庫匯入此 corpus，確認可信 Session 身分可映射題目帳號，保留資料與索引版本；不要覆寫目前示範資料。一次評估固定題庫版本、corpus 雜湊、程式 commit、切塊與模型設定、split 與執行 ID。

至少保存各題可檢索來源、實際 retrieved ID、送模型與 reranker 的 ID、交付引用、回答／拒答及評分理由；以來源 ID 驗證公司／ACL／版本隔離，以語意審查驗證事實與拒答，分開報告檢索命中、引用支持、答案正確、拒答正確及安全失敗。不要把這組完整性測試的通過率當作這些成效。失效帳號應在模型呼叫前阻擋。撤權與版本切換的競態仍須另寫整合測試，靜態快照不涵蓋。

題庫與 corpus 同用 `dataset_version: 1.0.0`；改動事實、ACL、預期行為或 split 時升 minor／major 版本並記錄理由，純文字錯字可升 patch。不要默改已評估的版本。`schema_version` 控制欄位格式。現階段沒有付費呼叫、成效數字、延遲或成本結論。
